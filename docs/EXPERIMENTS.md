### 这次真的测到了什么

#### 1. 新来源的生成图片

只用GPT1开发样本和原训练来源训练/选型，之后才打开GPT1.5、GPT2、nano-banana-pro及新真实来源考试。考试结果没有用于重新选模型或挪分界线。

| 外部生成来源 | 可分析脸数 | 原模型认出 | 验证集预先选定的候选认出 |
| --- | ---: | ---: | ---: |
| gpt-image-1.5 | 121 | 20 | 66 |
| gpt-image-2 | 24 | 5 | 11 |
| nano-banana-pro | 13 | 0 | 5 |
| 合计 | 158 | 25 | 82 |

陌生真脸共1002张：原模型误报15张，新候选误报57张。分别约1.5%和5.7%。其中FairFace镜像992张，DOCCI仅10张；不是所有真实照片的误报率。最终考试针对“检出并裁下的最大脸”，不包括未找到脸的图片，也不能直接当成整张多人照片的成绩。

| 外部检查 | 原模型 | 验证选定的候选 |
| --- | ---: | ---: |
| 认出生成脸 | 25/158（15.8%） | 82/158（51.9%） |
| 误报真脸 | 15/1002（1.5%） | 57/1002（5.7%） |

新候选来自验证集选择的 **multisource**，并非看完考试才选它。真实/生成数量差很多，因此没有只报一个“总准确率”来掩盖漏检。

#### 2. 照片篡改

原视频帧模型直接用到普通照片，有较明显误报。先在300张来源标为真实的原图上复查，篡改分支提示37张，生成分支提示9张；两项直接合并判假会更糟。

补入真实照片、可控局部修改后，验证集选出的照片候选为 **regional_supervision**。外部FairFace真脸误报从225/992降到126/992，仍约12.7%，依然不适合当鉴定工具。DOCCI的10张真脸两者都未误报，样本太少不能据此放心。

照片候选的正例主要还是FF++视频帧与程序制造的局部修改，**缺少足够多真正被改过的普通照片、截图、美颜及局部AI编辑的独立考试**。降低真图误报，不等于这些新篡改已经都会识别。

#### 3. 视频

先覆盖全段取样，再在可疑点附近补取，最多96个覆盖点和48个加密点；保留原来16帧规则做整段判断，另给短片段复核提示。不是把所有帧平均，也不是“有一帧高分就判假”。

后者在验证集140段真实视频中会误报86段，所以被弃用。仅用验证数据锁定“同一临时空间轨迹的相邻两帧均分”保守提示阈值，再看固定测试子集：

- 原整段规则：真实视频2/140触发，伪造视频134/140触发。
- 保守局部规则：真实视频0/140触发，伪造视频107/140触发。

局部规则在完整伪造片上检出更少，所以**没有替换整段规则**。0/140只是本次观察，不能说以后误报为零。该测试仍来自原FF++，不代表所有网络视频。

另造了同编码的真实对照与0.4/0.8秒替换片，用来检查平均分是否冲淡短暂问题。真实对照6段，原整段规则提示1段，局部规则提示0段；短暂替换片12段，原整段规则提示2段，局部规则提示3段，其中提示时间范围碰到预设替换区间3段。

原计划8组，2组原片与伪造片无法可靠对齐，明确排除，最终6组18段。这个小练习有新编码和对齐假设，只是构造的压力检查，不能冒充全新视频数据集。时间范围是建议复核的邻域，不是精确证明篡改从哪一帧开始。

局部提示在12段短暂替换片中也只抓到3段，**短片段漏检还很明显，没有解决完**。这也是保留原整段结果、把新增能力称为复核提示的原因。

#### 4. 你之前提供的GPT图片

修正了启动器中文路径编码后，已真正读入原图复查：实验生成分支返回“疑似生成”，分数约99.91/100；照片篡改分支返回“未检出明显篡改”。原文件校验值不变，标准化后的像素未出现在本轮训练或验证中。它是以前看过的用户回归图片，不是新盲测，也不能代替上面158张外部生成脸的成绩。没有上传或把原图放进仓库。

### 对你之前8个问题的回答，用这次结果来说

**1，数据少吗？** 不只是总数少。原来FLUX/SD3.5已足以把同来源分数练得很好，新GPT1验证样本却只认出6/25。加多来源后有进步，但陌生工具考试仍只认出82/158，还增加误报。同一个工具再加一万张，不保证补上这个缺口。

**2，能教它真正的破绽吗？** 做了一个可复查的尝试：从真图制造轻微错位、颜色和混合边界，并把已知修改区域的答案交给它。另做完全相同数据、只给真假标签的对照。两者验证分类指标约0.9401和0.9399，差距很小，不能宣称位置监督更好。

已知练习区域的像素排序指标约0.846，无位置监督约0.550，说明存在一些位置学习信号；但区域重合度约0.125，仍低，也没有真实伪造区域的人工答案。因此不把热区显示成“这里就是破绽”。这只是参考SBI/Face X-Ray思想的简化原创实验，不是论文复现，更不能用混合边界识别所有整脸生成。

**3，数据重复靠加量能解决吗？** 不能。43,521张图片筛出142对跨集合相似候选，查看前40对时发现至少一对明显同源照片，文件的人物标签却不同。142对不全是重复。为新实验保守隔离相关整组947张，原数据不动；老模型不会因为改了清单就自动变干净。还没有证明跨来源人物完全互斥，外观指纹也查不出所有变体。

**4，要给它考试纠正吗？** 训练像练习，验证像模拟考，用来选模型和分界线；最终考试只报成绩。看了最终错题再改模型，那份考试就成了开发材料，下一次需要新考试。本轮已经把这些顺序和文件分开，没有追着最终成绩改阈值。

**5，视频先统一抽帧再加密吗？** 已接入并实际检查。但抽得更多会增加误报，必须一起测。现在分别保留整段基线与短片段提示，给出可疑时间范围和最大采样间隔；采样间隙仍会漏，临时轨迹可能在人物交叉、切镜时串线，也没有真正学习连续动作。

**6，多人照片加训练就行吗？** 先修了只看最大脸的程序限制：对检出的脸逐一给结果，预览编号，可放大核对；一次最多32张，超额会说明。也补了一些真实照片的多脸裁剪。但小脸可能根本没被找到，真假混合的多人篡改照片考试仍缺；生成分支128像素输入也没凭空恢复细节。

**7，方案落地了吗？** 照片默认分别跑生成和篡改，两项、每张脸分别给分，不合成“真假概率”；还新增坏文件、无脸、部分失败和取消处理。新候选可单独打开，稳定权重不覆盖。分支之间会交叉触发，不能据此认定具体是哪种制作方式。

**8，兼容性呢？** 按你的要求暂缓新发布包、跨系统和其他电脑验收。本轮测的是这台机器源码环境，不能说所有队友电脑都已验收。

- 完成清理后重训5轮、多来源5轮、强化扰动5轮、位置监督4轮、标签对照4轮，以及冻结ViT特征的线性分类对照。不同模型使用同一验证人口排名，不按考试重排。

### 下一步优先做什么

1. 增加新工具和真正局部AI编辑的独立资料，同时补真实相机、截图、美颜、压缩等来源；保留后续新考试，别继续拿这次考试调参后仍叫盲测。
2. 先降低陌生真图误报，明确选择“宁可漏一些”还是“多提醒人工复核”；需要新的验证证据，不能拿本次外部57个误报直接挪线。
3. 给真实篡改区域补人工标注，检查位置监督是否在新来源有效；当前合成练习的地图不作为证据。
4. 多人真假组合、人物交叉、短片段、变帧率和长视频继续做独立检查。最后再按你确定的版本重新打包。

## FF++ 换脸基线

已完成现有 FF++ 数据上的独立参考实验：数据审计 → 冻结骨干对照 → 全网微调 → 验证集选择参数/阈值 → 测试 → 导出 → 原视频推理校验 → 桌面演示。

本报告记录第一阶段 FF++ 实验。新增整脸生成的当前联合模型见 整脸生成联合模型一节，首次跨生成器实验见 首次跨生成器实验一节；两个任务指标分别统计。

### 默认演示模型：全网微调

| 指标 | 冻结骨干对照 | 全网微调 |
| --- | ---: | ---: |
| 验证集视频 AUC | 0.6710 | 0.9827 |
| 测试集视频 AUC | 0.6447 | **0.9870** |
| 测试集 balanced accuracy | 60.00% | **96.25%** |
| 测试集 accuracy | 65.14% | 94.86% |
| 测试集伪造召回率 | 68.57% | 93.93% |

微调固定运行 4 轮，每轮每段训练视频取 4 张交错帧，轮换后合计覆盖全部训练帧。每轮使用完整验证集，选中第 **4** 轮，最后才对测试集评分。微调没有使用测试集选轮次、学习率或阈值。

微调实际耗时 **9.39 分钟**（不含导入启动），PyTorch 峰值 allocated 显存 **0.74 GiB**。视频阈值 0.497548。微调原视频一致性和 CPU/GPU 等核验耗时 40.4 秒。

| 实际类别 | 微调判真实 | 微调判篡改 |
| --- | ---: | ---: |
| 真实（140 段） | 138 | 2 |
| 篡改（560 段） | 34 | 526 |

| 微调各方法测试 | 视频数（包含真实） | AUC | balanced accuracy |
| --- | ---: | ---: | ---: |
| Deepfakes 对真实 | 280 | 0.9959 | 97.86% |
| Face2Face 对真实 | 280 | 0.9905 | 96.43% |
| FaceSwap 对真实 | 280 | 0.9941 | 98.21% |
| NeuralTextures 对真实 | 280 | 0.9676 | 92.50% |

默认 GUI 和命令行使用 `model_finetuned.pt`。全部预测与错误保存在 `finetuned_test_videos.csv`。这是已见四种篡改方法的 FF++ 库内测试；高分仍不能证明对陌生数据集或整脸生成有效。

### 冻结骨干对照的详细结果

| 指标 | 验证集（700 段） | 测试集（700 段） |
| --- | ---: | ---: |
| 视频 AUC | 0.6710 | 0.6447 |
| 视频 balanced accuracy | 64.64% | 60.00% |
| 视频 accuracy | 65.29% | 65.14% |
| 伪造召回率 | 65.71% | 68.57% |
| 伪造 precision | 87.83% | 84.96% |

AUC 衡量模型将伪造排在真实之前的能力；0.5 接近随机排序。balanced accuracy 将真实和伪造的召回率等权平均。数据真假数量为 1:4，不能只看 accuracy（全部猜假也有 80%）。

测试视频 AUC 的 95% 分组 bootstrap 区间为 [0.6254, 0.6694]，以 70 对官方测试来源组为重采样单位，500 次。该区间只反映此固定模型、此数据集的采样不确定性，不覆盖重复训练或现实分布变化。

视频阈值 0.493621、图片帧阈值 0.488128 均由验证集确定。分类层 C=0.1。测试集未用于选择这些参数。图片结果来自 FF++ 视频帧，不能据此声称对独立真实照片有效。

### 未见方法实验

冻结骨干实验中，训练和验证均排除 NeuralTextures，最终仅在 test 的真实 + NeuralTextures 共 280 段视频上测试：AUC **0.5528**，balanced accuracy **54.64%**，伪造召回率 59.29%。参数与阈值仅用其余已见方法的验证集确定。没有另做微调模型的未见方法实验，不可把两者成绩混为一谈。

这是 FF++ 内的方法留出；不能证明跨数据集、现代扩散生成器或任意网络视频泛化。此实验另存模型，主模型未被替换。

### 实际时间、资源和核验

- 留出方法实验：29.2 秒，复用冻结特征。
- 原视频/模型一致性等核验：41.6 秒。
- GPU：NVIDIA GeForce RTX 5070 Laptop GPU；主实验 PyTorch 峰值 allocated 显存 **0.67 GiB**。不包含驱动、其他进程和 reserved 显存；不能直接当成显卡总占用。
- 独立环境约 4.90 GiB，当前 artifacts 约 393.8 MiB，weights 约 44.9 MiB；D 盘剩余约 175.5 GiB。
- 全部 79,994 张图片成功解码；跨划分精确像素重复为 0；来源编号/组不跨 train/val/test。未做生物身份或近重复审计。
- 导出分类层与 sklearn 的最大验证分数差为 4.63e-07。
- 两种模型的 CPU/GPU 分数比较、原视频重新抽帧裁脸与清单评估分数比较、无脸图片返回“无法判断”、独立重算测试视频 AUC/平衡准确率均通过。批量/单图分数容差为 0.001，实际误差见 `verification.json`、`finetuned_verification.json`；这是浮点数近似比较，不是逐位相等。
- Python、Torch、GPU 与运行路径见 `metrics.json`；代码与模型校验值见 `reproducibility.json`。

## 整脸生成联合模型

本文件保留v0.1.0稳定生成模型的历史结果。本轮新来源训练、近重复审计与外部考试见 [2026-10-26报告](EXPERIMENTS.md#session-20261026)；当前源码自动模式会逐脸分别检查两项，稳定模型文件保留，实验候选需明确打开。下列旧划分分数不能替代新的跨来源考试。

已新增并接入独立的 AI 整脸生成检测。照片默认使用本联合模型，视频仍使用原 FF++ 换脸/面部篡改模型；照片要检查换脸时，在界面上方「检测项目」切换。两个任务不会混成一个分数。

### 数据是否补齐

**用于实验版训练的配套数据已补齐；GPT 专项训练和成规模独立测试仍缺少。**

本次处理了 LFW 13,233 张真实照片、FFHQ-256 镜像两个分片的 8,750 张真实照片，以及 FairFaceGen 的 FLUX / SD3.5 各 11,200 张生成照片。共 44,383 张候选，43,521 张通过同一 YuNet 裁脸与格式标准化；862 张 SD3.5 未检出人脸，算作无法判断，不标真实。新数据位于 reference_run/data，原数据和 FF++ 权重没有覆盖。

LFW 校验 scikit-learn 发布的 SHA256；FFHQ 镜像固定提交和 LFS SHA256；FairFaceGen 校验官方 MD5。FFHQ 镜像并非 NVIDIA 官方发布，没有完整身份和逐图原始许可元数据；未做生物身份、近重复去重或商用/再分发清理。因此这仍是可审计来源的研究原型，不是已经完成所有数据审查的生产基准。

### 为什么训练第二版

先完成了「FLUX 训练，SD3.5 完全留出」的实验。其未见 SD3.5 AUC 为 0.9508，但锁定阈值后的生成召回率只有 **18.03%**，说明排序能力和可用的判定阈值不是一回事，FLUX 的高分不能代表跨工具泛化。

第一版模型、预测、阈值和报告全部保留在 artifacts/generation 与 首次跨生成器实验一节。随后将 SD3.5 按预先固定的分组哈希划成 train/val/test，训练覆盖两种生成器的新版本；SD3.5 **不再称为本版本的未见生成器**。选择第二版是为了补上已发现的 SD3.5 能力缺口，不是把同一测试集重新命名为独立测试。

| 联合版划分 | 方法 | 图片数 |
| --- | --- | ---: |
| test | FLUX | 1,670 |
| test | SD35 | 1,513 |
| test | real | 3,065 |
| train | FLUX | 7,905 |
| train | SD35 | 7,311 |
| train | real | 15,798 |
| val | FLUX | 1,625 |
| val | SD35 | 1,514 |
| val | real | 3,120 |

已按 LFW 人物、生成种子分组；FFHQ 只能按图片分组，没有证明所有人物互斥。所有来源统一裁脸、128px / JPEG90；两类同样应用颜色、缩放、模糊、翻转与 JPEG 扰动，但来源捷径仍可能存在。

### 联合模型实际结果

固定 5 轮全网微调，真假、来源/生成器和已知身份分组均衡损失。仅用验证集选择第 5 轮；仅用验证集 balanced accuracy 最优区间中点确定阈值 **0.707737**，未用测试或用户图片调阈值。原始观察点阈值结果也保留在 pre_calibration_metrics.json。

| 已见生成器测试 | 图片数（含真实） | AUC | balanced accuracy | 生成召回率 |
| --- | ---: | ---: | ---: | ---: |
| FLUX 对真实 | 4,735 | 1.0000 | 99.95% | 100.00% |
| SD35 对真实 | 4,578 | 1.0000 | 99.92% | 99.93% |

两行包含同一批真实测试照片，不能相加当成独立真实样本。整体测试 6,248 张，AUC 1.0000，balanced accuracy 99.94%。额外 JPEG60 重压缩后 balanced accuracy 99.92%。

额外对未参与生成训练的 FF++ 真实测试视频各取一张人脸帧，共 140 张，误报率 0.00%；这是仅真实类的跨来源压力检查，不是完整跨库 AUC。评估不包含前述未检出脸的 862 张图片。

训练与初次正式评估 13.16 分钟，PyTorch 峰值 allocated 显存 0.74 GiB；校准和核验时间另计。非常高的库内成绩可能仍来自来源差异，不能推断对任意 AI 图片有效。

## 首次跨生成器实验

本次新增独立的整脸生成检测分支，保留原有 FF++ 换脸/面部篡改模型。默认照片进入生成检测，默认视频进入篡改检测；需要检查照片换脸时，可在界面上方切换「检测项目」。两个模型的分数不混成一个“真假概率”。

### 数据缺口如何处理

原来已有 FairFaceGen 的 FLUX 与 SD3.5 生成脸，缺少配套真实照片和整脸生成训练/评估。此次在 `reference_run/data` 独立保存并处理：

- LFW 13,233 张真实照片，通过 scikit-learn 固定的 SHA256 校验，按人物名称分组划分。
- FFHQ-256 公开镜像的两个分片，共 8,750 张照片，固定镜像提交版本与 LFS SHA256。它是发布者标注的 FFHQ 镜像，不是 NVIDIA 官方分发；没有附完整身份、作者和逐图许可元数据。
- FairFaceGen：FLUX 11,200 张用于分组划分；SD3.5 原始 11,200 张全部预留作未见生成器测试。
- 共 44,383 张候选图，成功裁脸并纳入 43,521 张；862 张 SD3.5 未检出人脸，返回“无法判断”，未视为真实，也未纳入有脸样本 AUC。SD3.5 人脸检测覆盖率为 92.30%。

| 划分 | 方法 | 来源 | 图片数 |
| --- | --- | --- | ---: |
| heldout_generator | SD35 | FairFaceGen | 10,338 |
| test | FLUX | FairFaceGen | 1,670 |
| test | real | FFHQ-256-mirror | 1,305 |
| test | real | LFW | 1,760 |

| val | real | FFHQ-256-mirror | 1,343 |
| val | real | LFW | 1,777 |

所有来源统一使用 YuNet 最大人脸、1.3 倍裁剪范围、128×128 与 JPEG90 编码；训练时再做两类相同的翻转、颜色、缩放、轻度模糊和 JPEG 扰动，降低格式捷径。统一编码不能消除来源差异，因此高分仍可能包含数据来源线索。

LFW 按已知人物分组，生成脸按种子编号分组；FFHQ 镜像按图片分组。已检查精确像素重复和分组跨划分；**未完成 FFHQ 的生物身份或近重复审计，不能声称全部身份互斥**。FairFaceGen 及镜像未附完整适用条款；当前是本地研究实验，没有确认商用或图片再分发资格。来源不明的第三方压缩包没有用于训练。

### 实际成绩
